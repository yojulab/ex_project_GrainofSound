# 법적 가드레일 · 폼 보안 · 모바일 접근성 및 성능 가이드

- **문서 참조**: [`docs/PRDs/gyeol.md`](file:///apps/ex_project_GrainofSound/docs/PRDs/gyeol.md) §1, §4, §5, §6
- **핵심 목표**: 비영리임의단체 법적 준수(후원 계좌번호/결제창 노출 절대 금지), 무로그인 공개 폼의 스팸/보안 방어, 모바일 및 중장년층 가독성·접근성, 1.5초 이내 초기 렌더링 성능을 동시에 확보한다.

## 1. 법적·운영적 가드레일 (Zero-Tolerance Legal Rules)

### 1-1. 후원 계좌번호 및 직접 결제창 원천 배제
- **법적 배경**: 고유번호증만 보유한 비영리임의단체 기준에 맞추어, 불특정 다수를 대상으로 한 공개 모금으로 오인될 수 있는 요소를 원천 차단한다.
- **절대 금지 항목**:
  1. 본문, 모달(`M01~M03`), 푸터(Footer), 메타태그, API 응답 내 **은행명 + 계좌번호 텍스트 노출 금지**.
  2. 신용카드/간편결제/계좌이체 등 **직접 후원금 결제 버튼 및 PG 모듈 연동 금지**.
- **필수 구현 프로세스**:
  - 반드시 **`[후원회원 가입 문의] 접수 → 담당자 확인 → 1:1 개별 연락(문자/카카오톡 또는 전화)을 통한 회비 납부 안내`** 프로세스로만 구현한다.
  - 후원 문의 모달 상단에 지정된 법적 안내 문구를 토씨 하나 누락 없이 명확히 표시한다.

### 1-2. 대외 창구 외 불필요 기능 배제
- 일반 방문자용 로그인, 회원가입, 마이페이지 UI를 생성하지 않는다.
- 내부 단원 연습 일정 캘린더, 악보/음원 자료실, 단원 전용 자유게시판 기능을 공개 웹에 포함하지 않는다.

## 2. 공개 3대 액션 폼 보안 및 개인정보 보호 규격

1. **스팸 및 봇 제출 방어 (Anti-Spam)**:
   - **Honeypot 필드**: 화면에 보이지 않는 숨김 입력 필드(`website` 또는 `_hp`)에 값이 채워진 요청은 즉시 차단한다.
   - **IP 레이트리밋**: 동일 IP에서 `/api/actions/*` 엔드포인트로 분당 5회 초과 요청 시 `429 Too Many Requests`를 반환한다.
   - **입력값 살균 (Sanitization)**: XSS 방지를 위해 모든 텍스트 필드의 HTML 태그를 이스케이프하거나 제거한다.
2. **연락처 및 필수값 검증 (Zod Validation)**:
   - 전화번호 형식(휴대전화 및 지역번호 포함 유선전화) 정규식 검증 및 하이픈 자동 포맷팅을 지원하여 중장년층 지원자와 복지관 담당자의 입력 편의성을 높인다.
3. **운영자 접수 확인 페이지 보호 (`/admin`)**:
   - 일반 방문자에게는 노출되지 않는 비공개 경로(`/admin/login`)로 격리하며, `robots.txt` 및 `noindex` 메타태그로 검색엔진 색인을 차단한다.
   - 비밀번호는 `bcrypt`(12 rounds 이상) 해싱, 5회 연속 실패 시 15분 계정 잠금(`lockUntil`), `HttpOnly` 세션 쿠키를 적용한다.
   - `.env` 환경변수 폴백(`|| 'default'`) 사용을 전면 금지한다.

## 3. 모바일 가독성 · 웹 접근성 (A11y) 및 카카오톡 인앱 대응

1. **중장년층 및 복지관 담당자 배려 타이포그래피**:
   - 본문 기본 폰트 크기는 최소 **`16px` (`1rem`)**, 줄간격은 **`1.65` 이상**을 유지한다.
   - 한지 배경(`#F6F3EC`) 및 고목 베이지(`#EAE4D7`) 위에 농묵(`#1A1917`), 담묵(`#5C564F`), 고목 브라운(`#4A3525`)을 배치하여 **명도 대비 4.5:1 이상**을 보장한다.
2. **모바일 터치 타겟 및 모달 접근성**:
   - 모든 액션 버튼(Section 05 및 Sticky Bottom CTA, 모달 제출/닫기 버튼)은 최소 높이 **`48px` 이상**의 터치 영역을 확보한다.
   - 모달 오픈 시 포커스 트랩(Focus Trap), `ESC` 키 닫기, `aria-modal="true"`, ` role="dialog"` 속성을 부여한다.
3. **대체텍스트 (`alt`) 필수 제공**:
   - Hero 비주얼 및 활동 아카이브 갤러리의 모든 공연 사진에 구체적인 대체텍스트(예: `"부천시 어르신 복지관 나눔 공연에서 장구 연주를 선보이는 연희단 결 단원들"`)를 제공한다.
4. **카카오톡 인앱 브라우저 `100dvh` & Safe Area 대응**:
   - 상하단 주소창 변화에 따라 레이아웃이 튀거나 가려지지 않도록 `100vh` 대신 **`100dvh`**를 사용한다.
   - 모바일 하단 고정 바(Sticky Bottom CTA)에 `padding-bottom: env(safe-area-inset-bottom)`을 적용하고, 페이지 최하단(Footer 아래)에 고정 바 높이만큼의 여백을 확보하여 푸터 정보가 가려지지 않게 한다.

## 4. 모바일 초기 렌더링 1.5초 이내 성능 목표

1. **이미지 최적화**:
   - 공연 아카이브 사진은 `WebP` 포맷으로 제공하며, 첫 화면(Hero) 외 모든 갤러리 이미지에 `loading="lazy"` 및 적절한 `sizes` 속성을 부여한다.
2. **폰트 로딩 최적화**:
   - `Cormorant Garamond`, `Noto Serif KR`/`MaruBuri`, `Pretendard` 웹폰트에 `font-display: swap`을 적용하여 텍스트가 즉시 표시되도록(FOIT 방지) 구성한다.
3. **성능 지표 목표**:
   - 모바일 데이터 환경 초기 화면 렌더링(FCP/LCP) **1.5초 이내**, CLS **0.05 이하**.
