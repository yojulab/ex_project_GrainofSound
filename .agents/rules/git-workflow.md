# Git 워크플로우 & 업무 종료 커밋 규약 (Git Commit Rules)

본 문서는 **비영리 전통연희단체 「연희단 결 (GYEOL : The Grain of Sound)」 공식 웹페이지 구축 프로젝트**(`docs/PRDs/gyeol.md`)에서 모든 에이전트와 개발자가 작업을 수행하고 종료할 때 준수해야 하는 **Git Commit 표준 지침**이다.

---

## 1. 커밋 시점 및 의무 원칙

### 1-1. 업무 단위별 Git Commit 필수
- 에이전트는 디자인 토큰 구축, 원페이지 섹션 퍼블리싱, 3대 액션 모달 구현, MongoDB(`grain_of_sound`) 스키마 작성, API 엔드포인트 구현, 카카오톡 OG/인앱 최적화 등 **유의미한 단위 작업(WBS G-01 ~ G-12)을 완료할 때마다 반드시 Git Commit을 수행**해야 한다.
- Ralph Loop 실행 중에도 각 마일스톤이나 서브태스크가 완료되면 즉시 커밋하여 디스크 상에 상태를 영속화(State on Disk)한다.

### 1-2. 원자적 커밋 (Atomic Commits)
- 여러 영역의 작업을 한데 뭉뚱그려 커밋하지 않고, 독립적인 기능/섹션/모달/API 단위별로 원자적으로 커밋한다.
- 커밋 전 `git status`와 `git diff`를 확인하여 의도하지 않은 임시 파일이나 비밀키(`.env`)가 포함되지 않았는지 점검한다.

---

## 2. 커밋 메시지 컨벤션

커밋 메시지는 다음 접두어와 WBS ID(`G-01` ~ `G-12`)를 연계하여 명확히 기술한다:

| 타입 | 의미 | 예시 |
| :--- | :--- | :--- |
| **`feat:`** | 신규 섹션 UI, 모달 폼, API 구현 | `feat(ui): 한지·먹색 디자인 토큰 및 Hero(100dvh)·About 섹션 구현 [G-04, G-05]`<br>`feat(modal): 3대 핵심 액션 모달(공연신청/단원지원/후원문의) 및 카톡 직통 연결 [G-09]` |
| **`infra:`** | 포트 30030, 도메인, MongoDB `grain_of_sound` 설정 | `infra(env): neptune.axfoundly.com(Port 30030) 및 grain_of_sound DB 연동 [G-01]` |
| **`arch:`** | Mongoose 데이터 모델 및 스키마 정의 | `arch(db): grain_of_sound 4대 핵심 스키마(공연신청/단원지원/후원문의/아카이브) 정의 [G-03]` |
| **`docs:`** | 작업지시서, README, 운영 가이드 | `docs: 연희단 결(GYEOL) 프로젝트 README 및 기동 매뉴얼 갱신` |
| **`rule:`** | 하네스 규칙, 에이전트 역할, 전용 스킬 갱신 | `rule: 연희단 결(GYEOL) v1.0.0 하네스 엔지니어링 헌장 및 전용 스킬 구축` |
| **`test:`** | 법적 가드레일(계좌 미노출), 100dvh, E2E 테스트 | `test(qa): 후원 계좌번호 노출 0건 및 3대 액션 모달 제출 E2E 검증 [G-12]` |
| **`chore:`** | 환경 설정, .gitignore, 패키지 의존성 관리 | `chore: Next.js App Router + TypeScript + Tailwind 초기 설정 [G-01]` |

## 3. 커밋 전 보안 및 법적 가드레일 체크리스트

1. **비밀정보 배제**: DB 패스워드, 세션 시크릿, SMTP 자격증명이 담긴 `.env` 파일이 스테이징되지 않았는가? (`.gitignore` 확인)
2. **법적·운영 가드레일 준수**:
   - 본문, 모달, 푸터 어디에도 **후원 계좌번호나 직접 결제 버튼**이 포함되지 않았는가?
   - 일반 방문자 로그인/회원가입이나 내부 연습 일정 게시판 등 범위 외 기능이 포함되지 않았는가?
3. **인프라 규격 일치**: 도메인(`https://neptune.axfoundly.com`), 포트(`30030`), DB명(`grain_of_sound`)이 일관되게 반영되었는가?
